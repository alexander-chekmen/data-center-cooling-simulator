Simulation Control

These controls call the simulator's API on :8090 and change the physics. They never write to the dashboard. The collector then reads the consequences over Modbus, so what you see on the left is the effect arriving back through the real pipeline 1–3 s later.

SERVER LOAD

Sets requested utilization. Chain: utilization → power (non-linear, idle is not zero) → heat → coolant and air loops → temperature. Temperature lags by minutes — racks have thermal mass, so watch it climb rather than jump.
Apply pins the racks at that level. Release hands them back to the automatic baseline.

SCENARIOS

Presets applied to all 24 racks. Overload drives the floor past design cooling capacity; Hot spot loads only A03–A05, so you can watch neighbouring racks warm through recirculation.

EQUIPMENT FAULTS

Faults are grouped by what they can actually affect. Pump and fan faults break the physics — heat stops leaving. Communication faults leave the equipment healthy and break only your view of it.

ACTIVE FAULTS

ENVIRONMENT

Push humidity high and the CDU is forced to raise coolant supply temperature to stay above the dew point — cooling capacity falls with no equipment fault anywhere.

TIME

Speeds up the simulation clock so slow thermal responses play out in seconds. Polling cadence stays real-time.
Reset releases all pinned load, clears every fault, returns humidity to automatic and the clock to 1×.
